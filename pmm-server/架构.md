按现在的环境，`pmm-admin list` 里显示 `Metrics Mode: push`，所以可以明确说：

1. **QAN 查询数据不是 pmm-server 主动去数据库拉取的**
2. **Metric 指标数据也不是数据库主动推给 pmm-server 的**
3. 真正主动做事的是 **pmm-client 上的 agent/exporter**

数据库本身通常是被动的：它提供接口、状态、日志或 `system.profile`，但不会主动把数据推给 PMM Server。

**三个角色**
```text
MongoDB / MySQL / PostgreSQL
  被监控对象。提供 metrics、状态接口、慢查询日志、profiler 数据。

pmm-client
  采集端。运行 exporter、profiler agent、pmm-agent、vmagent 等。
  它负责连接数据库、读取数据、整理数据，并发送给 pmm-server。

pmm-server
  存储和展示端。接收 pmm-client 上报的数据，存储到内部组件，然后通过 PMM UI/Grafana/QAN 展示。
```

**QAN 数据流向**
以 MongoDB profiler 模式为例：

```text
MongoDB
  ↓ 被 pmm-client 主动读取
pmm-client / mongodb_profiler_agent
  ↓ 主动上报
pmm-server / QAN 存储
  ↓ UI 查询展示
PMM Query Analytics
```

也就是：

```text
MongoDB system.profile  <--读取--  pmm-client  --发送-->  pmm-server
```

不是：

```text
pmm-server --拉取--> MongoDB
```

也不是：

```text
MongoDB --主动推送--> pmm-server
```

你现在看到的：

```text
mongodb_profiler_agent Running
```

说明 `pmm-client` 上有一个 agent 在做这件事：

```text
用 pmm 用户连接 MongoDB
读取 app_db.system.profile
把查询摘要/慢查询数据发送给 PMM Server
```

如果是 Real-time QAN，则类似：

```text
MongoDB 当前操作/诊断信息
  ↓ 被 rta_mongodb_agent 读取
pmm-client / rta_mongodb_agent
  ↓ 上报实时 query bucket
pmm-server
  ↓
Query Analytics -> Real-time
```

**Metric 指标数据流向**
你现在 `pmm-admin list` 里是：

```text
mongodb_exporter   Running   push
node_exporter      Running   push
vmagent            Running   push
```

这表示 metrics 的实际链路通常是：

```text
MongoDB
  ↓ 被 mongodb_exporter 主动读取
pmm-client / mongodb_exporter
  ↓ 暴露/整理成 Prometheus 格式
pmm-client / vmagent
  ↓ remote write / push
pmm-server / VictoriaMetrics
  ↓ Grafana 查询展示
PMM Dashboards
```

换成一行：

```text
MongoDB  <--读取--  mongodb_exporter  <--采集--  vmagent  --push-->  pmm-server
```

所以 metric 数据也不是数据库主动推给 PMM Server。数据库只是被 exporter 查询，比如读取：

```text
serverStatus
collStats
dbStats
replSetGetStatus
currentOp
```

真正推送到 PMM Server 的是 `pmm-client` 上的 `vmagent`。

**关于图里的箭头**
你图里左侧 exporter 到 PMM Server 的方向，大体表达“数据从 PMM Client 进入 PMM Server”，这个方向可以理解为正确。

但如果图表达的是：

```text
Prometheus 主动 scrape pmm-client exporter
```

那这是比较老的 PMM/Prometheus pull 模型。你现在的环境显示：

```text
Metrics Mode: push
```

所以你当前实际更接近：

```text
exporter 在 pmm-client 本地采集数据库
vmagent 从本地 exporter 取指标
vmagent push 到 pmm-server
```

不是 PMM Server 直接去 scrape 你的 MongoDB，也不是 MongoDB 主动推送。

**最终结论**
```text
QAN:
数据库产生 profiler / 查询信息
pmm-client 主动读取
pmm-client 主动上报到 pmm-server
pmm-server 存储并展示

Metrics:
数据库提供状态接口
pmm-client 上的 exporter 主动读取
pmm-client 上的 vmagent 主动推送到 pmm-server
pmm-server 存储到 VictoriaMetrics 并由 Grafana 展示
```

所以你的两个问题直接回答是：

```text
1. QAN 查询数据是否是 pmm-server 主动拉取？
不是。通常是 pmm-client 的 QAN agent 从数据库读取后上报给 pmm-server。

2. Metric 数据是否是数据库主动推给 pmm-server？
不是。数据库不主动推。pmm-client 的 exporter 读取数据库指标，再由 vmagent 推给 pmm-server。
```
